# Search catalog

The master search indexes local source records and a finite snapshot of the same
regional source endpoints already used by the app. A layer does not need to be
enabled before its names can be found. Search is not a claim that the upstream
sources describe every business, species or event in the region.

`node scripts/build-search-index.mjs` is an offline, deterministic build. It reads
the existing data files and writes `search-index.json` only when their content
changes. The index uses dictionary columns, omits geometry/full descriptions,
and orders navigation/species/sky and upcoming-event records before large
historical datasets. `decodeSearchCatalog` yields ordinary records incrementally.
No observations, invented facts or network calls are generated by this build.

## Coverage and opening

The catalog covers all named local record collections: history and fossils,
incident archives, movies, concerts, comedy, sports, food-truck stops, local
operators, gyms, parks, cycling/joyride routes, birding locations, outages,
geologic units, wildlife taxa from the stored regional observations and species
counts, sky objects/constellations, observing sites, river station names, and
named road references. Layer names and supported history/wildlife/geology/sky
subviews are included. `search-actions.js` adds the remaining existing tools and
sort choices at runtime.

`search-sources/` supplies named restaurants, bars, nightlife, recreation,
arts/history places, parking, EV sites, markets, development, neighborhoods,
county/municipal/school/legislative geography and existing calendar records.
Every source records its actual source observation/verification dates, source
URL and license. Large geometries and detailed source properties are fetched
only when a matching result is selected. `resolveSearchFeature` retrieves the
original stable-ID feature. Road and observing-site adapters preserve their
source geometry and attribution. Species selections open the existing species
browser; sky objects open the existing chart.

The source snapshot excludes the same known chains/cinemas as the app, omitted
features and unnamed footways. Unnamed placeholders are not useful search hits.
Wildlife taxa are indexed once per species, not once per observation; private,
obscured and threatened species are not introduced. Live species autocomplete
and loaded current layer records can supplement the static index. Air, weather,
traffic and moving vehicles are not frozen into a misleading current-data index.

At initial capture, 28 of 29 existing endpoint/mode requests returned usable,
nontruncated data. The `communityevents:meetings` source returned unavailable;
its mode remains navigable but no invented meetings are indexed. Both City and
County are included in the common regional bounds; no jurisdiction toggle is
introduced. Source failure is not evidence that an event or place was removed.

## Maintenance

The restricted morning runner remains restricted to the selected jobs. After
its event jobs, it runs the finite dynamic inventory with:

```
node scripts/refresh-search-sources.mjs --dynamic
```

This rereads only the existing upcoming-calendar endpoint inventory (concerts,
comedy, movies, sports, community/exhibition/free events, festivals and food
trucks), including the public-meeting mode. It does not discover new sources or
rebuild geology/history/parks/roads. Failures and truncated results retain the
last successful file and its verification date. Responses differing only in
verification timestamps do not rewrite files. Source failures appear in the
existing maintenance report. The offline index rebuild runs after selected
maintenance jobs so newly collected incidents/events become searchable.

Static POI/geography capture is explicit and is never part of the daily command:

```
node scripts/refresh-search-sources.mjs --only restaurants bars
```

The allowed source/mode inventory is exported by that script. Add/revise static
sources only for a concrete correction, upstream change or requested feature.
When adding a new local dataset, add its normalized record adapter to the build
and exact source resolver if its structure is not GeoJSON. Safe source filenames
are restricted to root JSON files, `search-sources/` JSON and dated incident
archive JSON. Shared source URLs never become arbitrary fetch targets.

## Verification

```
node scripts/search-catalog-test.mjs
node scripts/search-source-retention-test.mjs
```

The tests check every generated feature can resolve its original ID and full
properties; preservation across compact encoding; Blue Jay/Blues/geology/sky
coverage; excluded cinemas/unnamed records; deterministic repeated builds;
filename boundaries; last-successful retention on failure/cap; and updates on
actual reschedules without timestamp-only publication churn.
