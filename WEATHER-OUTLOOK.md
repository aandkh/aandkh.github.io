# Seven-day outlook

`weather-outlook.js` exports `appendWeatherOutlook(host, {lat, lng, signal?})`, returning `{ready, destroy}`. Call it only after the user opens Full forecast. Include `weather-outlook.css`; the module does not import images, icons, charts or additional styles by itself. Destroy the instance when that view closes or changes location. Reusing the same host automatically destroys its previous instance, preventing a late response for an old location from replacing the current outlook.

`loadWeatherOutlook` resolves the requested coordinate through the official NWS `/points/{lat},{lng}` endpoint, then follows its validated `/gridpoints/.../forecast` link. This uses the same four-decimal point key and shared `weatherJson` cache as the hourly forecast: one-day point metadata and five-minute forecast data. Cold loading makes at most two source requests; cache hits and concurrent subscribers share requests. A shared ten-second abort deadline covers both calls. Cancellation belongs to the subscriber, so closing this outlook does not cancel another active weather view. There is no persistent location history or new analytics.

The [official NWS API documentation](https://www.weather.gov/documentation/services-web-api) describes the linked `/forecast` resource as day/night periods over the next seven days. This UI shows up to seven calendar rows with separate daytime highs, nighttime lows, conditions and precipitation chances. Each native disclosure expands to the source's full written forecast, source period times and wind. Early-morning overnight periods belong to the preceding night, preventing accidental pairing with the following night. Missing values are explicitly unavailable; zero precipitation chance remains zero. Values in Celsius convert to Fahrenheit. The API's point timezone controls calendar boundaries and displayed time labels.

The displayed update time comes from NWS `updateTime` (or `generatedAt` when absent), never the fetch time. Invalid source times, source dates more than 24 hours old, and timestamps over 15 minutes in the future are unavailable. Expired or malformed periods are discarded. Coordinates remain the user's requested location even if nearby points resolve to the same source grid. The official forecast link uses those same coordinates. All source strings render as plain text.

Validation: `node --test scripts/weather-outlook-test.mjs`. Eight tests cover day/night and overnight pairing, null/zero probabilities, Celsius and stale times, the two-request budget, shared point-cache reuse, location changes, subscriber cancellation, safe text rendering and late results after destruction.

Live NWS verification on 2026-11-17 returned the LSX 88,74 grid for 38.63, −90.4, timezone America/Chicago and 14 current forecast periods. The source update was 2026-11-17T02:21:15Z. The first period was Tonight, 35°F, Clear, 0% precipitation. Two cold development-environment requests took about 4.0 and 3.5 seconds; an already cached point avoids the first request. These are source checks, not a promise of end-user latency.
